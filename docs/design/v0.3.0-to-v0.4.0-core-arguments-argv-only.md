# v0.3.0 → v0.4.0 — core arguments are argv-only (no env), a security invariant

> **STATUS (2026-07-28) — IMPLEMENTED except the tiers follow-up.**
> Landed: `env:"-"` on the controls and `Config` (fw/conf), the
> structural refusal (`rules/tags.ContribEnvRule` — a core
> contribution field without `env:"-"` is a registration violation),
> the injection pin tests, and completion's env-blindness — which
> landed BETTER than specified: the system facade's introspection
> view is environment-blind by construction (fw systemservice.go),
> so every introspection consumer inherits it. The controls'
> config-file door ("for now") is now owned by the
> field-source-tiers design.

## What we want to change

**No core argument is ever readable from the environment.** The
environment must never be able to alter a binary's closure, redirect
its config source, or trigger a serving surface. Core arguments are
argv-only; the operator running the command is the only party who
sets them.

Per-field policy:

| Core field | env | file | notes |
|---|---|---|---|
| `config` | `env:"-"` (ADD) | already `dump:"-"` | env-set config path is the root redirect vector — an attacker's file becomes the binary's config |
| `write-config` | `env:"-"` (present) | `dump:"-"` | serving surface |
| `help` | `env:"-"` (present) | `dump:"-"` | serving surface |
| `validate-config` | `env:"-"` (present) | `dump:"-"` | serving surface |
| `upgrade-config` | `env:"-"` (present) | `dump:"-"` | serving surface |
| `--enable-*` / `--disable-*` | `env:"-"` (ADD) | **file: allowed for now** | closure control; env exposure removed, file retained pending a later decision |
| `--override` | `env:"-"` (ADD) | file: allowed for now | same as enable/disable |
| `--applets` | `env:"-"` | run-scoped | new surface (applets-listing design) |

The controls (`enable`/`disable`/`override`) keep their config-file
door for now — a config file is already a trusted artifact in the
deployment's control, and closure shaping from a file is a legitimate
deployment pattern. Only the ENV door closes on them. (A later
decision may revisit files; not this change.)

## Why

- **Live bug** (found 2026-07-20 while discussing completion env
  reads): `coreControls.Disable/Enable/Override` (main.go:243-245)
  carry `conf:"…"` with **no `env:"-"`** — so today
  `MYBIN__DISABLE=…` can drop a service from the closure, and
  `MYBIN__ENABLE` / `MYBIN__OVERRIDE` can force-inject or remap a
  dependency, from the ambient environment. `conf.Core.Config`
  likewise has no `env:"-"`: an env-set config path redirects the
  binary to an arbitrary file. These are ambient-authority
  injection surfaces — the environment is not a trusted input on a
  multi-tenant or setuid-adjacent host.
- The rule "none of the core arguments are available as env" is a
  standing security decision; the code drifted from it. This change
  makes the invariant explicit AND enforced, not folklore.
- Completion did not cause this — it surfaced it by reading env
  (closure-truth). With core arguments argv-only, completion reading
  env can no longer see closure changes it must never honor from
  that source.

## What we expect it to touch

- **fw**: `coreControls` fields gain `env:"-"` (and stay file-
  settable for enable/disable/override; add `dump:"-"` only where a
  field must not round-trip); a test asserting no core field derives
  an env name.
- **conf**: `engine.Core.Config` gains `env:"-"`; a test that the
  core contribution exposes zero env names.
- **The invariant, enforced structurally**: `NewSchema`/the core
  contribution path should REFUSE a core/contribution field that
  lacks `env:"-"` (a commit-time assertion, so the next core field
  added can't silently reopen the hole) — this is the real fix, not
  just tags. Design the assertion so a deliberate exception is
  impossible for core, argv-only by construction.
- **spec**: §6 core arguments — state argv-only as a security
  invariant with the rationale; §5 controls note the file-yes/env-no
  split.
- **completion**: MUST disable environment access in general — the
  per-keystroke plan behind `Introspector.Arguments` runs with the
  env source off entirely (a nil env lookup / FeatureEnvironment
  suppression at the introspection seam). With core arguments
  argv-only, env could no longer shape the closure anyway; after
  this, completion queries consult argv-words and files only, and
  the interactive shell's environment is never read at all. Tests:
  an env-set control is not honored by the completion plan, and the
  plan's env lookup is never called.
- **sxcli-vet**: a ledger row / check — a core-tier field without
  `env:"-"` is a violation (statically visible; the structural
  assertion's static mirror).
- **CHANGELOG**: security-relevant behavior change.
