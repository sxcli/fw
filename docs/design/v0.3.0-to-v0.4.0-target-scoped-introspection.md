# v0.3.0 → v0.4.0 — target-scoped introspection

**STATUS (2026-07-29) — IMPLEMENTED** (fw: interface + view +
snapshot + uniform ejection; completion: engine `System`/`Source`
alias + both adapters; determinism and scoping pinned in both repos).
Deliberately outstanding: line-carried controls in the solve (rides
explicit-control-vocabulary, per What-4).

## What we want to change

1. **`System.Introspector(applet string) Introspector`** — the
   introspection view is constructed *per target*: the method runs the
   binary's real dispatch resolution on `applet` (the dispatch NAME —
   the token a command line carries; never a service ID) and solves
   that applet's closure against the catalog snapshot. The returned
   view serves **only facts from the target's resolved graph**: its
   arguments, sections, metadata domains. Nothing outside the closure
   exists in the view.
2. **Unknown or ambiguous name → nil.** A completion caller can do
   nothing with prose — no error channel; nil means "offer nothing".
3. **`Introspector("")` is the binary view**: it offers the applet
   names (the visible set, aligned with the `--applets` listing rules;
   hidden and system applets stay out of the listing but resolve by
   exact name through `Introspector(name)`). It does not carry the
   core's arguments — ruled 2026-07-29: no need, every target view
   already carries them.
4. **The target solve consumes the catalog and the completed line's
   arguments only.** `--enable`/`--disable` present on the line under
   completion are honored — they are argv. No config files, no
   location search, no environment: the view holds no runtime seams at
   all. Introspection becomes input-deterministic — same binary, same
   line, same answer, always. File-carried enables do not shape
   completion; that under-offer is the accepted trade. (Line-carried
   controls ride the explicit-control-vocabulary implementation; until
   it lands the solve is catalog-only, which is a subset of "arguments
   only", never a superset.)
5. **Ejection becomes uniform.** The
   never-eject-when-the-closure-contains-the-Introspector special case
   (today keyed to `system.ID` in main.go) retires: the completion
   applet's own closure ejects other applets like every closure; the
   target solve is data-plane work over the catalog snapshot, not
   admission.

## Why

- The 2026-07-29 system-service review proved the env→closure vector:
  the introspection view's location search reads
  `$XDG_CONFIG_HOME`/`$HOME`, and a redirected config's `core.enable`
  changed completion output. No patch closes this class; removing the
  input does.
- Per-applet completions are required regardless; the catalog-wide
  view over-offers and violates the scoping rule now ratified:
  **introspection must not return anything outside the target
  applet's resolved graph.**
- The ejection special case was a wart bridging completion to applet
  data; the design-status audit flagged the joint re-decision. This
  is it.
- With no env and no files in the view, the env-blindness claims in
  the-system-service and core-arguments-argv-only stop carrying an
  asterisk and become literally true.

## What we expect it to touch

- **fw/system**: the `System` interface
  (`Introspector(string) Introspector`), doc comments, the ""
  semantics.
- **fw** `systemservice.go`: dispatch+solve per call; the `lookupEnv`
  override is superseded by having no env door at all; no locations,
  no file loading.
- **fw** main.go: special case removed; dispatch resolution exposed
  as a pure function (single home — the method and the real run share
  it).
- **sxcli-completion** bash/zsh: extract the target token from the
  line, call `Introspector(target)`, nil → no candidates; first-token
  completion via `Introspector("")`.
- **Docs amended**: one-applet-per-closure (carve-out removed),
  the-system-service and core-arguments-argv-only (absolute wording
  now true).
- **sxcli-vet**: stubs follow the signature; whatever mirrors System
  usage follows.
- **Tests**: target-scoped view pins, nil-on-unknown, "" listing
  view, and a determinism pin — `XDG_CONFIG_HOME`/`HOME`/any env must
  not change introspection output (the review's proof becomes the
  regression test).
