# v0.3.0 → v0.4.0 — `--applets`: the listing leaves `--help`

## What we want to change

1. `--help` stops listing applets. Help is the **dispatched applet's**
   document: its argument schema, its positionals, its closure — not
   a directory of the binary.
2. A new core argument `--applets` prints the binary's public applets
   and exits 0: one per line, primary alias plus the first line of
   the applet's doc/usage. Hidden and System applets are excluded
   (same filter as `Introspector.Applets()`). Argument-only and
   run-scoped (`env:"-"`, `dump:"-"`) — invocation data, never
   configuration.
3. `--applets` is recognized **pre-dispatch**: `mybox --applets` has
   no selector word, so it must serve before dispatch would fail. It
   reads the catalog (immutable Build result, per the
   catalog/working-set split) — no resolution, no config load, no
   applet eject involved.
4. The dispatch-failure usage text stops embedding the applet list
   and points at `--applets` instead.

## Why

- The applet listing in `--help` conflated two documents: "how do I
  use the applet I'm running" and "what does this binary contain".
  With one-applet-per-closure, help's scope is the invocation;
  enumerating the binary is a catalog question and gets a catalog
  door.
- Pre-dispatch serving is what makes `mybox --applets` work at all in
  a multi-applet binary — there is deliberately no applet to
  dispatch to.
- Completion keeps its own catalog door (the Introspector);
  `--applets` is the human's equivalent.

## What we expect it to touch

- **fw core**: `--applets` knob (peeked with the core, pre-dispatch
  short-circuit in `run()` before `dispatch()`); listing renderer
  reading the catalog.
- **fw main.go**: `usage()` (dispatch failure) drops the applet list,
  gains the `--applets` pointer; help renderer drops the listing
  block if it has one.
- **Suppress vocabulary**: `FeatureApplets` in fw's Feature vocab
  (suppressible like help/write-config surfaces).
- **completion**: `--applets` completes as a core argument; one
  engine test.
- **spec**: §5 dispatch/usage section; §6 core arguments table.
- **sxcli-vet**: no new checks (runtime surface); ledger row noting
  the moved listing.
- **Breaking**: operator-visible (`--help` output shape) — v0.4.0.
